	# AI-Driven Surveillance Drone: IEEE-Style Software Requirements Specification Using Agile Software Engineering

	## Abstract

	This document presents the Software Requirements Specification (SRS) for an **AI-Driven Surveillance Drone** developed using the **Agile Software Engineering methodology**. The proposed system combines an unmanned aerial vehicle (UAV), artificial intelligence, computer vision, sensors, GPS, wireless communication, and a ground-control interface to support autonomous or semi-autonomous surveillance. The system is designed to detect objects, monitor predefined areas, transmit live video, identify potential security events, and provide alerts to authorized operators.

	The development process follows Agile principles, where the system is divided into incremental modules and developed through short iterations or sprints. Requirements are continuously reviewed, tested, and refined based on stakeholder feedback.

	**Keywords:** AI, Surveillance Drone, UAV, Computer Vision, Agile Software Engineering, Object Detection, GPS, Real-Time Monitoring, Autonomous Drone.

	---

	# I. INTRODUCTION

	## A. Background

	Traditional surveillance systems depend heavily on fixed cameras and human operators. Such systems have limited coverage when monitoring large, remote, or difficult-to-access areas. An AI-driven surveillance drone can overcome these limitations by providing mobile, aerial, and intelligent monitoring capabilities.

	The proposed system uses a drone equipped with cameras and sensors to collect real-time information from the surrounding environment. Artificial intelligence techniques can process the captured video to detect objects, people, vehicles, restricted-area entry, and other predefined events.

	The system can operate under human supervision and may support autonomous navigation within predefined boundaries. A ground-control application provides the operator with live video, drone position, system status, alerts, and mission information.

	## B. Purpose

	The purpose of this project is to develop a software system for an AI-driven surveillance drone that can:

	* Monitor a predefined geographical area.
	* Capture and transmit real-time video.
	* Detect predefined objects using AI.
	* Track detected objects.
	* Generate alerts for suspicious or predefined events.
	* Provide GPS-based drone location.
	* Allow authorized users to control and monitor the drone.
	* Store relevant surveillance data for later analysis.

	## C. Agile Development Approach

	The system will be developed using **Agile Software Engineering** rather than implementing the entire system in a single development cycle.

	The project will be divided into several sprints:

	| Sprint   | Major Deliverable                                      |
	| -------- | ------------------------------------------------------ |
	| Sprint 1 | Requirement analysis and system architecture           |
	| Sprint 2 | Drone communication and basic flight-control interface |
	| Sprint 3 | Camera and live-video streaming                        |
	| Sprint 4 | AI-based object detection                              |
	| Sprint 5 | Object tracking and event detection                    |
	| Sprint 6 | GPS, geofencing, and mission management                |
	| Sprint 7 | Alert system and data storage                          |
	| Sprint 8 | System integration, testing, and optimization          |

	At the end of each sprint, the implemented functionality will be tested and reviewed. Feedback will be incorporated into subsequent sprints.

	# II. USERS

	The system shall support different categories of users.

	## A. System Administrator

	The administrator is responsible for system configuration and management.

	**Responsibilities:**

	* Manage authorized users.
	* Configure system parameters.
	* Configure surveillance zones.
	* Manage AI detection settings.
	* Review system logs.
	* Manage stored surveillance data.
	* Monitor system health.

	## B. Drone Operator

	The drone operator controls and monitors the drone during surveillance missions.

	**Responsibilities:**

	* Start and stop surveillance missions.
	* Monitor live video.
	* View drone location.
	* Control the drone when manual control is enabled.
	* Define surveillance areas.
	* Receive security alerts.
	* Monitor battery and connectivity status.

	## C. Security/Monitoring Personnel

	Security personnel primarily use the system for surveillance monitoring.

	**Responsibilities:**

	* Observe live drone video.
	* View AI-generated detections.
	* Review alerts.
	* Review recorded surveillance data.
	* Report suspicious events.

	## D. Maintenance/Technical User

	The maintenance user is responsible for technical operation and maintenance.

	**Responsibilities:**

	* Diagnose hardware and software faults.
	* Update system software.
	* Check sensor status.
	* Maintain communication modules.
	* Verify drone and camera functionality.

	# III. FUNCTIONAL REQUIREMENTS

	Functional requirements describe what the system shall do.

	## FR-01: User Authentication

	The system shall provide authentication for authorized users.

	The system shall:

	* Accept valid username and password credentials.
	* Reject invalid credentials.
	* Provide role-based access.
	* Prevent unauthorized users from controlling the drone.

	## FR-02: Drone Connection

	The system shall establish communication between the ground-control application and the drone.

	The system shall:

	* Detect the drone connection status.
	* Display connection status to the operator.
	* Establish communication before starting a mission.
	* Notify the operator when communication is lost.

	## FR-03: Live Video Streaming

	The drone shall capture video using an onboard camera and transmit it to the ground-control application.

	The system shall:

	* Display live video.
	* Provide video status information.
	* Handle temporary communication interruptions.
	* Allow authorized users to start and stop video streaming.

	## FR-04: AI-Based Object Detection

	The system shall analyze the camera stream using an AI-based computer vision model.

	The system shall be capable of detecting configured object categories such as:

	* Person
	* Vehicle
	* Animal
	* Other predefined objects

	The system shall display detected objects with appropriate bounding boxes and confidence values.

	## FR-05: Object Tracking

	The system shall track detected objects across successive video frames.

	The system shall:

	* Assign a tracking identifier to detected objects.
	* Maintain tracking while the object remains visible.
	* Update the object's position.
	* Handle temporary loss of detection.

	## FR-06: Event Detection

	The system shall identify predefined surveillance events.

	Examples include:

	* Entry into a restricted area.
	* Presence of an unauthorized person.
	* Detection of a vehicle in a restricted zone.
	* Unusual movement.
	* Drone entering a prohibited area.

	## FR-07: Alert Generation

	The system shall generate alerts when predefined surveillance events occur.

	An alert shall contain relevant information such as:

	* Event type.
	* Time of event.
	* Drone location.
	* Detected object.
	* Confidence value, where applicable.
	* Snapshot or video reference, where available.

	## FR-08: GPS and Location Monitoring

	The system shall obtain and display the drone's geographical position.

	The system shall display:

	* Latitude.
	* Longitude.
	* Altitude.
	* Flight path.
	* Current mission area.

	## FR-09: Geofencing

	The system shall support predefined geographical boundaries.

	The system shall:

	* Define permitted surveillance areas.
	* Detect when the drone approaches a boundary.
	* Generate an alert when a geofence violation occurs.
	* Prevent or restrict flight outside configured boundaries where supported by the flight-control system.

	## FR-10: Mission Management

	The operator shall be able to create and manage surveillance missions.

	A mission may contain:

	* Mission name.
	* Surveillance area.
	* Waypoints.
	* Flight altitude.
	* Mission duration.
	* Detection configuration.

	## FR-11: Drone Status Monitoring

	The system shall display important drone status information, including:

	* Battery level.
	* GPS status.
	* Communication status.
	* Camera status.
	* Flight mode.
	* Altitude.
	* Speed.
	* Position.

	## FR-12: Data Storage

	The system shall store relevant surveillance information.

	Stored information may include:

	* Video recordings.
	* Images.
	* Detection results.
	* Alerts.
	* GPS coordinates.
	* Mission information.
	* System logs.

	## FR-13: Mission Control

	Authorized operators shall be able to control supported drone operations through the ground-control interface.

	The system shall support appropriate commands such as:

	* Arm/disarm.
	* Take-off.
	* Landing.
	* Return-to-home.
	* Mission start.
	* Mission pause.
	* Emergency stop or appropriate emergency procedure.

	## FR-14: Reporting

	The system shall provide surveillance reports containing information such as:

	* Mission duration.
	* Flight path.
	* Detected objects.
	* Generated alerts.
	* Mission status.
	* Recorded events.

	# IV. NON-FUNCTIONAL REQUIREMENTS

	Non-functional requirements define the quality attributes and operational constraints of the system.

	## NFR-01: Performance

	The AI detection system should process video with sufficiently low latency to support real-time surveillance.

	The system should minimize:

	* Video processing delay.
	* Alert generation delay.
	* Communication latency.

	## NFR-02: Reliability

	The system shall continue operating reliably under normal environmental and communication conditions.

	The system should detect failures such as:

	* Camera failure.
	* GPS failure.
	* Communication failure.
	* Low battery.
	* Sensor failure.

	## NFR-03: Availability

	The ground-control application and drone communication system should be available throughout an active surveillance mission, subject to network and hardware limitations.

	## NFR-04: Security

	The system shall protect access to the drone and surveillance information.

	Security mechanisms should include:

	* User authentication.
	* Role-based authorization.
	* Secure communication.
	* Access control.
	* Secure storage of sensitive surveillance data.

	## NFR-05: Scalability

	The software architecture should allow additional drones, sensors, AI models, and surveillance zones to be integrated in future versions.

	## NFR-06: Maintainability

	The software shall use a modular architecture so that individual components can be modified without significantly affecting other components.

	Example modules include:

	* Flight Control Module.
	* AI Detection Module.
	* Video Processing Module.
	* GPS Module.
	* Communication Module.
	* Alert Module.
	* Database Module.
	* User Interface Module.

	## NFR-07: Usability

	The ground-control interface shall be simple enough for an authorized operator to understand the drone's status and perform common operations without unnecessary complexity.

	## NFR-08: Accuracy

	The AI detection module shall provide reliable object detection within the capabilities of the selected AI model, camera, environmental conditions, and available computing hardware.

	## NFR-09: Fault Tolerance

	The system shall respond safely to failures.

	For example:

	**Communication failure → Detection → Alert → Appropriate failsafe behavior**

	**Low battery → Detection → Warning → Return-to-home/emergency procedure**

	## NFR-10: Portability

	The software should be designed so that the AI and monitoring components can be deployed on compatible embedded computers, edge devices, or ground stations.

	## NFR-11: Privacy

	The system shall restrict access to captured surveillance data to authorized users and should avoid unnecessary collection or retention of personal information.

	# VI. CONSTRAINTS

	## A. Hardware Constraints

	The performance of the system depends on the available onboard computing hardware, camera resolution, battery capacity, sensors, and flight controller.

	Limited onboard processing power may reduce AI inference performance.

	## B. Battery Constraint

	Drone flight time is limited by battery capacity, payload weight, weather conditions, and flight behavior.

	The system must therefore monitor battery status and support appropriate low-battery procedures.

	## C. Network Constraint

	Real-time video and remote control require a reliable communication link. Poor network conditions may cause:

	* Video latency.
	* Packet loss.
	* Reduced video quality.
	* Communication interruption.

	## D. AI Model Constraint

	AI detection accuracy depends on:

	* Training data.
	* Lighting conditions.
	* Camera quality.
	* Object size.
	* Weather.
	* Object orientation.
	* Processing hardware.

	Therefore, AI predictions cannot be assumed to be 100% accurate.

	## E. Environmental Constraints

	The drone may be affected by:

	* Wind.
	* Rain.
	* Fog.
	* Dust.
	* Low-light conditions.
	* Temperature.
	* Obstacles.

	The system must operate only within the capabilities of the selected drone and hardware.

	## F. Regulatory Constraints

	The drone must be operated in accordance with applicable aviation, privacy, and local regulations. Autonomous operation, surveillance, flight altitude, restricted areas, and data collection may be subject to regulatory requirements.

	## G. Computational Constraints

	AI inference and video processing require significant computational resources. The system may therefore need edge computing, GPU/NPU acceleration, or processing on a ground station depending on the selected hardware.

	## H. Safety Constraints

	The system shall prioritize safe drone operation over surveillance functionality.

	Safety mechanisms should include:

	* Return-to-home.
	* Geofencing.
	* Low-battery detection.
	* Communication-loss handling.
	* Obstacle avoidance where supported.
	* Manual override for authorized operators.
