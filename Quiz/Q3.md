# Quiz Assignment 3

## Questions

1. In Postman, an API returns HTTP 200, but a test checking the response field completed fails. Give one possible reason?

2. How does comparing expected and actual results help in intelligent debugging?

3. Why should regression tests be executed after modifying an existing software feature?

4. How can response-field validation improve API quality assurance?

5. A test passes for one API endpoint but fails for another endpoint in the same collection. What should be checked first, and why?

## Answers

1. **One possible reason** is that the response contains the field `completed`, but its value does not match the value expected by the test. For example, the test expects `true`, while the API returns `false`. HTTP 200 confirms request success, not the correctness of every response field.

2. **Comparing expected and actual results** helps identify exactly where the software behaviour differs from the requirement. This narrows down the possible cause of a defect, makes debugging more focused, and helps developers verify whether the fix resolves the issue.

3. **Regression tests should be executed** after modifying an existing feature to ensure that the change has not broken previously working functionality. They help detect unintended side effects and maintain the stability and reliability of the software.

4. **Response-field validation improves API quality assurance** by checking that required fields are present, correctly named, have the expected data types, and contain valid values. It can detect incorrect or missing data even when the API returns a successful HTTP status code.

5. **First, check the endpoint-specific request and test configuration**, including the URL, HTTP method, headers, parameters, request body, and expected response values. Different endpoints may return different data structures or values, so a test written for one endpoint may not be valid for another.
